# RTX 4060 Laptop 本机兼容性验证 — 2026-09-06

## safe.1 报错的具体原因

本机为 NVIDIA GeForce RTX 4060 Laptop GPU，驱动 616.64。只读原始接口返回 132 个请求槽位：前 127 个（0～126）是核心曲线；127 号是 600 mV / 405 MHz 的显存域点，和 24 号核心点电压重复。safe.1 未读取条目域，把它混入核心曲线后按电压排序，触发严格递增校验。因此出现“曲线布局/数值异常”。截图中的这次读取没有应用曲线。

还确认了第二个缺陷：safe.1 的 9248 字节控制表总长度虽然正确，但按 72 字节条目解释是错误的，且读取控制表未提供设备请求掩码。仅去掉重复电压保护会留下错误写入/备份风险。

## 一手开源项目检索

- [simple-nvidia-undervolt](https://github.com/vuplea/simple-nvidia-undervolt)，MIT，Windows CLI，直接读写 NVIDIA 曲线；文档预期支持 RTX 40，但检索时未找到其 4060 Laptop 已确认报告。其标准 CLI 调参默认会持久化，因此本次不直接运行默认调参命令或预设。
- [G-Helper NVIDIA 后端](https://github.com/seerge/g-helper/blob/main/app/Gpu/NVidia/NvidiaGpuControl.cs)：使用 Pstates20 核心/显存偏移与 nvidia-smi 限频，不能等同于完整曲线编辑；整套工具主要面向 ASUS，不直接安装到本机测试 OEM 功能。
- [ColorControl 曲线实现](https://github.com/Maassoft/ColorControl/blob/master/ColorControl/Services/NVIDIA/NvGpuInfo.cs)：有 V3/V1 曲线路径，可作协议对照；不同版本结构不可混用。本次未运行整套应用。

测试用的 simple-nvidia-undervolt 源码版本为 [`beace06d9b17d0e614d0925360f84456d1320d2a`](https://github.com/vuplea/simple-nvidia-undervolt/tree/beace06d9b17d0e614d0925360f84456d1320d2a)。仅在隔离的本地测试程序中链接其未经修改的 NVAPI 源文件，保留 MIT 许可；未启动其安装、开机持久化、清零或预设命令。没有把该项目源码复制进应用发行文件。

## 实机证据

用户明确同意本机写入测试，并确认保存工作、退出游戏和调参程序后进行。管理员确认由用户完成。

1. 只读交叉验证：独立开源接口得到 127 个核心点，450～1240 mV，电压无重复。只读预览前后偏移不变。范围是读回数据，不是降压建议。
2. 开源接口单点测试：900 mV / 核心槽 72，从 2250 MHz 临时降到 2235 MHz，随即恢复。
3. 修正后的本项目原生后端重复相同测试；由独立开源 getter 核对，单点频率、全部 255 个偏移和完整控制表字节变化与预期一致。
4. 两次测试均确认恢复后的控制表和偏移与备份完全一致；P0 核心/显存配置与电压提升百分比不变。测试温度约 47°C。备份落盘后才写入，并启动独立恢复进程；正常恢复后取消其动作。

原始日志、完整设备标识和备份只保存在本地被 Git 忽略的 `bin/`，不提交或上传。读取工具在 `tests/NvApiReadOnlyProbe`；该项目仅含固定读取入口，不需要管理员权限，不调用写入或启动整个控制中心。

## 修复及边界

safe.2 使用驱动报告的 256-bit 请求掩码；状态表 0x40 起 28 字节条目、控制表 0x40 起 36 字节条目，偏移字段在 +24。核心曲线在首个非核心域结束，不删除核心域中的重复电压、不排序掩盖异常、不从后续槽重新收集“看似核心”的项。完整读改写保留不相关字段；0 号锚点不写入，通过最终读回验证。

备份内容升级到版本 2，拒绝旧版 128 槽数据，恢复路径仍保留旧文件以便发现问题。

safe.2 阶段验证的是单点协议、正确点位及原始状态恢复。没有修改 CPU CO、CPU 功耗、BIOS、驱动安装或系统启动项；不能据此认定历史黑屏重启已解决。

## safe.3：用户再次授权的整段曲线测试

用户要求完整构建并发布 Release，而非仅做读取或模拟测试；退出旧版程序后，通过新的 Windows 管理员确认执行。

- 使用生产 `NvidiaGpuController` 的预设预览、应用、手动恢复和后端 60 秒超时恢复入口；隔离测试构造函数只解除对 WPF/CPU/风扇配置宿主的依赖，不替换曲线写入代码。
- RTX 4060 Laptop / 616.64，起始温度 46°C，初始全部曲线偏移为 0。900 mV 锚点原有频率 2250 MHz；完整平台修改了 54 个点，无频率提升，无显存或 CPU 写入。
- 两次应用均通过独立开源 getter 核对：完整原始控制表字节、全部 255 偏移、P0 核心/显存/电压设置；900 mV 及右侧读回均为 2250 MHz。
- 第一次由公开恢复入口恢复；第二次不确认保留，等待生产后端 60 秒计时器恢复。两次均恢复到原始表和偏移，应用恢复记录在完整验证后移除。另有独立恢复进程和不可覆盖的本地原始备份，正常完成后恢复进程未执行额外写入。
- 新预设以本机实际曲线为准，不把 2250 MHz 当作所有机器的常量；已有偏移、错误型号或曲线需要任何频率提升时拒绝生成。
- 显存查询实机返回 405、810、6001、7001、8001 MHz，确认原基础/Boost 上下限算法错误；没有实测 `-lmc` 显存写入，不能把列表存在当作写入能力保证。

实机原始备份、PCI 标识和诊断日志继续仅保留在忽略的本地 `bin/`。**未进行长时间游戏/压力负载、功耗收益、驱动挂起或系统崩溃恢复测试**；短时整段读写成功不等于通用稳定认证。
